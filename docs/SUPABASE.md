## Важное отличие Supabase migrations от Prisma migrations

Начальная схема создана через Supabase MCP, а не `prisma migrate deploy`. Эти две истории миграций не синхронизируются автоматически. **Не запускать `npm run db:migrate` на этой базе вслепую:** Prisma попытается создать уже существующие объекты.

После приватной настройки подключения нужно:

1. Сверить существующую схему с Prisma и обоими SQL-файлами.
2. При подтверждённом совпадении отметить обе уже выполненные миграции как применённые через Prisma `migrate resolve --applied 0001_initial` и `migrate resolve --applied 0002_server_only_access` (с загрузкой приватного окружения).
3. Проверить `prisma migrate status`.
4. Новые изменения выполнять одним согласованным путём через versioned Prisma migrations. Не применять одну миграцию двумя инструментами.

## Следующие шаги подключения

1. Настроить приватные URL для runtime pooler и DDL/migration-соединения в окружении приложения. Выбрать режим pooler, совместимый с Prisma и средой Vercel; параметры брать из Connect в конкретном Supabase-проекте. Не помещать пароль в GitHub, чат или `NEXT_PUBLIC_*`.
2. Выдать серверному приложению минимальные права: чтение каталога, создание/обновление нужных полей заявки. Не использовать публичный Supabase key для обхода RLS и не выдавать браузеру административные ключи. DDL выполнять отдельно от runtime-роли.
3. Заменить JSON-источник каталога на Prisma, подключить поиск к тому же источнику, добавить кеширование и состояние отказа БД без скрытой подмены демоданными.
4. Добавить идемпотентное сохранение заявки после валидации и антиспама, до отправки почты; затем обновление статуса и возможность повтора уведомления. Текущая модель требует дальнейшей миграции для устойчивой идемпотентности.
5. Подключить Resend, Turnstile и persistent rate limit; проверить домен и почтовые DNS-записи. Не включать `CONTACT_ENABLED`, пока весь путь не проверен и privacy policy не согласована.
6. Проверить реальные запросы Prisma, сбои БД/почты, повторные отправки и права доступа на preview deployment. Проверки исходного каркаса не доказывают работу интеграции.
7. Согласовать сроки хранения заявок, доступы, мониторинг и возможность резервного копирования/восстановления на выбранном тарифе. Бесплатный проект не означает production SLA или наличие нужных backup-функций.
